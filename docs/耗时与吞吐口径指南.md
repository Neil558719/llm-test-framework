# 耗时、首内容与成功吞吐

`throughput_rps` 保留完成尝试吞吐：测量批次的完成样本数除以实际 wall time。失败、429和成功均属于完成尝试。`goodput_rps` 使用相同 wall time，分子为 `SampleResult.success`：HTTP或SSE完成事件满足 Reference chat 最小有效响应契约。成功必须有正确类型的 answer、sources、tool_calls、conversation_id、trace_id；200空对象不能成功。可选 usage/cost 也必须有效。

这是有效协议响应吞吐，不是未经业务验证的业务质量吞吐。工单失败、拒答或模型 fallback 仍可能是有效响应；已有 `SampleExpectation` 继续独立检查业务状态、工具失败及成功条件，不能用高 goodput 抵消失败的业务门禁。`latency_ms` 是所有样本的延迟分布；`success_latency_ms` 只使用成功样本，空分布为null。warmup仍不计入批次样本或 wall time。

新增 `min_goodput_rps` 可配置成功吞吐下限，保留 `min_throughput_rps` 的原尝试吞吐含义。全500可以产生很高尝试吞吐，goodput仍为零，不能满足正的成功吞吐下限。两项不自动互换。

## 三种耗时

- Reference `response.latency.total_ms` 用单调时钟从 `_run_chat` 入口计至业务、封装和成本计算完成，在响应序列化及trace emit前回填。它包括本地存储/业务运行，不包括HTTP鉴权、网络传输、响应序列化及遥测sink开销，是服务端处理耗时；响应与同一trace使用相同值。
- 场景顶层 `latency_ms` 用单调时钟测对话执行窗口，包括adapter调用和步骤断言，不含adapter初始化、最终断言及Judge评测。没有实际进入对话窗口时为null；中断对话可有已耗时间，但依然不完整、不能通过。UTC字段只作为时间戳，不拿墙钟差值冒充单调耗时。
- 压测 `duration_ms` 是客户端从发起尝试至得到并校验响应/终止的耗时，包括网络与客户端协议处理，与前两种不同。场景报告保留自己的测量，不把服务端耗时或Judge耗时相加冒充客户端请求时间。

场景报告JSON/HTML显示对话耗时，A06 importer已有的null处理继续保留。在线缺失 `total_ms` 输出null，不补零；趋势跳过缺值，并保留原有规则：不将离线p95当作原始样本和在线延迟混算，不追认旧默认零为真实测量，不回填旧结论。

## SSE建立、内容和TTFT

`stream_established` 表示收到2xx且Content-Type是text/event-stream（可有charset）。这不等于已收到内容。HTTP错误、429、连接建立前超时不属于已建立流；建立后的超时、坏JSON、无效完成事件、缺少complete都属于中断。错误样本保留已经得到的HTTP状态和首内容计时。

`content_first_event_ms` 只在首个非空字符串chunk到达时记录。start、注释、空chunk和complete均不能创建此时间；complete-only可为合法完成，但首内容与TTFT保持null。summary给出首内容分布、`stream_established_count`和`stream_modes`；中断率分母为已建立流，无此分母时为null，配置了对应门禁会按缺测拒绝。

Reference现有实现是先生成完整回答再切块发送，start和完成响应metadata均标 `stream_mode=simulated`。这些chunk只能证明客户端看见内容的时间，不能证明模型首token时间；Reference的envelope及压测兼容TTFT字段均不生成模型TTFT。

未知外部流保留旧 `ttft_ms` 的合法客户端首内容别名，同时标 `ttft_source=client_first_content`、summary `ttft_kind=legacy_client_first_content; not model TTFT`。这保持旧network首内容能力，不信任对方自报model类型来创建模型TTFT资格。模拟流的别名为null，首内容仍正常统计；若到complete才获知simulated，会清除别名。

新增 `max_content_first_event_p95_ms` 直接检查客户端首内容；旧 `max_ttft_p95_ms` 沿保留的兼容测量检查，缺值拒绝，不改阈值。包内M13模拟流配置从 `max_ttft_p95_ms: 1000` 迁移为 `max_content_first_event_p95_ms: 1000`，阈值和负例含义保留。这里没有新增供应商真实streaming接口，也没有把模拟数据当真实模型效果。

包内M13的 `max_stream_interruption_rate: 0` 从全局移到唯一SSE场景，数值仍为0。HTTP没有已建立流，不可套用此门禁；HTTP无分母null不等于流成功。若用户仍在HTTP阶段配置流门禁，继续按缺测拒绝，而非忽略阈值。七个故障/恢复场景的本地ASGI验证使用显式Mock零价表，成本阈值及完整性仍保持原规则。

## 兼容和验证边界

SampleResult、LoadTestSummary、ScenarioRunResult新增字段追加在原字段后；原位置参数不移动。旧手工summary没有成功吞吐证据时默认null，不推算成功吞吐；旧手工SSE样本应显式提供已建立状态，不能把全部SSE尝试猜作已建立。HTTP/SSE正向测试夹具须符合声明的最小响应契约，畸形响应负例继续保留。

A06 manifest、可信来源选择、baseline可比性、required质量、应用授权及TTL不因观测字段改变。版本仍dev6，后续dev7集成由主流程执行。离线替身、TestClient与临时SQLite只能验证接线；真实供应商、生产负载、HTTPS/IdP和持久部署验收仍待相应环境，用户复现与掌握未评估。
