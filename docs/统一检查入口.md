# 统一检查入口

开发默认 Python 3.12，CI 保留 3.12 / 3.14；发行包的 Python >=3.9 承诺不变。
先按 `uv sync --locked --extra ci` 安装锁定依赖，再运行：

```text
python scripts/check.py --tier smoke --mode offline
python scripts/check.py --tier core --mode offline
python scripts/check.py --tier full --mode offline
python scripts/check.py --tier full --mode offline --collect-only --out reports/check-inventory
```

`scripts/check-manifest.json` 是显式清单。新增、删除测试文件或改名必需节点后，
必须同时更新清单；未知文件、陈旧节点、空集、收集错误和缺依赖均返回非零。
smoke 明确执行 5 个启动、最小业务/工具契约和门禁负例节点。
core 执行 A01–A08 修复、统一入口守卫和三条关键业务流程所在的声明文件。
full 执行所有声明的离线节点并检查 5 个场景 YAML 与 3 个 Web 资源。
每一档先收集完整实际 node ID，以便逐项解释未执行的内容。

报告在 `reports/check-<tier>-<mode>/check-report.json`，也可用 `--out` 指定目录。
`check-report-v1` 包括 `selected`、带原因的 `excluded`、逐节点/阶段 `executed`、
`commands` 和退出码、`counts`、`errors`、资源 hash。相邻保留收集/执行的 XML、
日志和退出码。只收集时状态为 `collected`，已执行/通过数为 0，不能当作测试通过。
只有实际所选节点与执行记录完全一致、每个节点 setup/call/teardown 各一次且均通过，
入口才报告 `passed`。意外 skip、xfail、xpass、收集漂移、进程零退出但缺证据均失败。
入口不加载自动发现的第三方 pytest 插件，不接受断言重跑参数；只加载清单声明的插件。

离线子进程会移除继承的凭据、供应商/应用配置和 pytest 过滤参数，并显式设为 Mock。
即使父进程有 `DIFY_AGENT_KEY` 或真实模型配置，也不能据此切换到供应商调用。
日志和报告不得加入真实业务数据或密钥。

独立环境验收始终逐项显示 not-run：5 个 UI 节点、2 个 Windows 计划任务/watcher 节点、
1 个真实 Compose CLI 配置节点。PowerShell 模拟参数测试仅在解释器可用时执行；
POSIX 模拟参数测试仅在原生 POSIX 环境执行，Windows 不借 Git Bash 补数。
这些排除不会被称为 full 已覆盖的 UI、系统或 Docker 验收。
UI workflow 保留独立任务，并明确检查 Chromium 依赖和全部 5 个测试无跳过。
容器/负载/安装包任务继续独立；本地 full 不能替代它们。

`--mode live` 保留统一接口，但当前任务没有声明真实目标、请求预算和独立验收套件，
因此明确输出 `not-run` 并返回非零，不尝试调用，也不把缺配置后的跳过当成功。
真实 Dify/Judge/Embedding 仍需单独批准的目标、预算和环境验收。

CI 增加 master push，原 `Offline tests (Python …)` 名称不变，接入 full；
新增 `smoke checks (Python …)` / `core checks (Python …)`，均保留两版本矩阵。
workflow 源码并不证明分支保护已启用：已保存的远端读取显示 master 未受保护，
required checks 的配置、故意失败 PR、当前 SHA Actions、合并/Release/环境仍待主流程验收。
旧 `scripts/ci_run.py` 是历史入口，不用于本次强制检查；其 skip 和 rerun 缺口的
主动失败复现保留在 `docs/evidence/X02/legacy_gap_reproducer.py`。

CI 全局 `UV_PYTHON=python` 显式选择 setup-python 配置的 PATH 解释器，避免
开发默认 `.python-version=3.12` 覆盖 3.14 矩阵。容器任务也先 setup Python 3.12。
