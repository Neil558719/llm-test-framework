# 趋势、线上离线关联与发布验证指南

里程碑17在 M15/M16 的脱敏 Trace、反馈、人工复核和回归晋级之上，提供可查询的趋势、显式线上/离线关联以及可复现的发布验证。所有示例使用临时 SQLite 和占位版本，不调用真实供应商或公网服务。

## 完整闭环

平台只接受明确的关系：

```text
Trace -> Feedback -> Review -> Promotion -> scenario_id
      -> offline RunReport -> baseline/candidate -> Release Validation
```

创建关联时必须同时提交 `promotion_id`、`offline_run_id` 和匹配的 `scenario_id`。平台会校验晋级记录未过期、场景 ID 在离线运行中存在；不会根据名称、时间或文本猜测关联。

## CLI

先准备一个已经由离线 Runner 生成、包含 `application`、`release_id`、`version` 和 `environment` 元数据的 RunReport JSON：

现有 `v1-api-gate` 可直接写入这些元数据，例如：`v1-api-gate --application reference-agent --release-id alpha-23 --version candidate --environment offline`。

A06 原生 gate 在执行前冻结独立计划并写 qe-run-v2。导入时仍需操作者独立选择可信 manifest；自携 manifest、verification 或旧 gate=True 均不能自授信。先根据受控资产保存计划，再执行，不可从已经产出的结果反造期望集合：

```python
import json
from pathlib import Path
from qe_platform.scenarios import load_scenarios
from qe_platform.reporting.integrity import freeze_run_manifest

plan = freeze_run_manifest(load_scenarios("qe_platform/scenarios/assets/reference_agent"))
Path("trusted-plan.json").write_text(json.dumps(plan.as_dict(), ensure_ascii=False), encoding="utf-8")
# 此后对同一受控资产执行 v1-api-gate，分别生成 baseline/candidate 报告。
```

```text
quality-loop import-run --database C:/Temp/m17.db --report reports/baseline.json --manifest trusted-plan.json --source-label ci-fixture
quality-loop import-run --database C:/Temp/m17.db --report reports/candidate.json --manifest trusted-plan.json --source-label ci-fixture
quality-loop link --database C:/Temp/m17.db --promotion-id <promotion-id> --offline-run-id <candidate-run-id>
quality-loop trends --database C:/Temp/m17.db --json reports/trends.json --html reports/trends.html
quality-loop validate-release --database C:/Temp/m17.db --baseline <baseline-run-id> --candidate <candidate-run-id> --json reports/release.json --html reports/release.html
```

`validate-release` 默认要求候选运行自身通过、覆盖 baseline 的场景集合、失败率为 0、通过率不下降、关联线上低质量率不增加。可显式传入 `--max-candidate-failure-rate`、`--max-pass-rate-drop` 和 `--max-low-quality-rate-increase`；退出码 0 表示通过，1 表示门禁失败，2 表示输入或配置错误。

A06 额外始终要求不同run ID、同应用、相同环境、完整 verified_v2 与一致控制资产，`--allow-incomplete` 不能绕过这些前置条件。相同用例ID改输入、setup、工具/断言、rubric或threshold需新baseline；模型/prompt实验版本允许变化并记录。自定义evaluator的评分规则须通过freeze_run_manifest(scoring_assets=...)显式冻结；默认资产记录实际JudgeSpec/提示规则。缺 --manifest 仍可导入结构合法的只读历史观察，import退出0只表示导入成功，不能当发布通过。相同ID不同执行内容拒绝覆盖。

## API

查询接口：

- `GET /api/quality/trends?application=&version=&from=&to=`：按 UTC 日桶、应用和版本返回线上/离线指标。
- `GET /api/quality/links?offline_run_id=&promotion_id=`：返回显式关联链。
- `GET /api/quality/release-validations/{validation_id}`：读取发布验证证据。

production 查询需要登录，viewer、reviewer、releaser、admin 中任一现有角色可读；匿名 401，无业务角色 403，读取无需 CSRF。写接口可使用既有 `X-QE-Telemetry-Token`，或 production 的 releaser/admin 人类身份（Cookie 写入需要 CSRF）；显式 development 下机器写入仍要求 token：

- `POST /api/quality/offline-runs`：导入脱敏 RunReport。
- `POST /api/quality/links`：创建或幂等返回线上/离线关联。
- `POST /api/quality/release-validations`：执行门禁；失败返回 422，同时保留完整 checks。

这些质量写接口没有 reporter_id/reviewer_id 字段；A04a 未新增此类字段。离线 run 当前通过导入接口和趋势/links 间接查询，没有独立 run 列表/详情或 evidence GET。A04b 按服务器 subject/application 映射限定查询和计算，机器 token 仅能写配置允许的应用；Link和baseline/candidate必须同应用，即使身份同时获授两个应用也不能跨应用关联。新生产 validation 由服务端保存 scope_application/scope_policy_version 证明；旧无证明记录不自动取得生产发布资格。详见[应用范围授权指南](应用范围授权指南.md)。

HTTP 信任只能来自 `create_telemetry_app(..., trusted_manifest_resolver=...)` 或仓库的服务端 resolver；resolver 按受控配置返回独立预选计划，不能直接信任入参的 manifest。body expected_manifest 拒绝400。上传v2缺独立信任标为unverified_manifest；旧summary为legacy_unverified，均无发布资格。新发布记录另有report_policy_version=2；生产读取缺/未知证明的历史验证返回404，不回填旧结论。原A04b授权、actor和CSRF规则保持。

## 报告指标

趋势 JSON/HTML 包含：线上 Trace 数、反馈数、确认低质量数和比例、离线运行数和通过率、P95 延迟、Token、成本，以及 Trace/Feedback/Review/Promotion/Scenario/Run 的 ID 关联。没有分母的比例为 `null`，不会伪造 0/1 结论。HTML 是自包含文件并对动态值转义，页面包含趋势、离线运行对比、关联链和发布门禁检查表。线上原始延迟存在时，P95 只由线上原始样本计算；同一日只有一个离线汇总时展示其 P95，同一日有多个离线汇总但没有线上原始样本时返回 `null`，避免把多个已聚合 P95 当作原始样本再次计算。

发布验证中的每项检查包含 `name`、`actual`、`threshold`、`passed` 和 `message`，因此失败原因可直接用于 PR 或发布记录。baseline/candidate RunReport 只保存结构化指标和场景 ID，不保存用户问题、Agent 答案或工具原始参数。

v2安全投影还保存实际步骤/必需质量覆盖、内容/响应/控制摘要和安全来源标签；Mock来源保留，不安全标签脱敏并留摘要。HTML区分Reported gate、Verification和Release eligible，历史通过观察显示UNVERIFIED，不是当前可信发布PASS。完整评估但质量失败可complete=True/passed=False；缺grounding、未配置evaluator、执行中断或inconclusive不完整。错误报告保留实际步骤及原因，不补后续调用。缺失/null的可选latency表示未测量，不能补0；required质量score缺失仍阻断。

quality_loop schema1→2自动迁移保留旧payload/IDs/links/历史验证，旧记录只读未验证；readiness由repo动态要求schema2。质量库合成恢复使用expected_versions={"quality_loop":2}，旧reader回退需匹配迁移前快照，不能只回退代码或伪改schema版本。现有deploy恢复脚本只管理Agent库，该范围未扩大；详见[A06证据](evidence/A06/summary.md)。

## 隐私、保留与隔离

平台沿用 30 天 Trace 保留边界；过期 Trace、反馈、复核和晋级不可查询或建立关联。离线运行和发布验证保留自身审计记录，但读取已过期线上链路时返回空关联。上传内容会拒绝请求/回答明文、Authorization、API key、Cookie、Token、Bearer 值和绝对路径标签。

线上数据和测试数据使用不同记录类型：线上只引用脱敏 Trace ID，离线只保存 RunReport 指标。M17 不在被测 Reference Agent 中加入质量断言，不需要真实供应商凭据。FastGPT 不属于本项目范围，也没有对应依赖、适配器、测试或 CI 验收。
