# Milestone 9: V1 reports, API E2E, and CI gates

## Goal

Deliver a reproducible V1 quality gate for the reference IT service desk Agent and publish the first stable `v0.1.0` release.

## Constraints

- Reference Agent and test platform remain separate.
- FastGPT is out of scope; Dify remains only a secondary adapter target.
- Offline Mock execution must not require real API keys or external services.
- Preserve `AppResponse` and existing `ScenarioRunner` APIs.
- Functional E2E, UI, load, and telemetry remain separate execution modes.
- Delivery follows Issue -> branch -> local tests -> Push -> PR -> Actions -> review -> merge -> Release -> deployment/tracking.

## Tasks

### 1. Unified run report

- Add `qe_platform/reporting/` models and JSON/HTML writers.
- Aggregate scenario results, pass/fail counts, failed steps, assertion differences, tool calls, and business-state differences.
- Add focused tests for serialization, deterministic output, and failure summaries.

### 2. API E2E and gate command

- Add an offline API E2E runner that executes the packaged Reference Agent YAML scenarios through the existing adapter.
- Add a command/module entry point that writes JSON and HTML reports and exits non-zero for incomplete or failed required scenarios.
- Add tests covering happy paths, error/recovery paths, and gate failure behavior.

### 3. CI integration

- Extend GitHub Actions to run the V1 gate on Python 3.12 and 3.14.
- Upload JSON/HTML reports as artifacts and preserve failure logs.
- Keep Docker readiness and existing regression jobs intact.

### 4. V1 release evidence

- Update the development-process status table and this plan with exact test/CI evidence.
- Add V1 release notes and deployment/tracking evidence.
- Publish stable `v0.1.0` only after merged-master verification, review, Actions, and gate evidence pass.
