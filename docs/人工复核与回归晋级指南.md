# 人工复核与回归用例晋级指南

里程碑 16 在 M15 脱敏 Trace/反馈 API 之上增加人工复核和回归用例晋级。Trace 只保存指纹、长度、工具摘要、版本与指标；原始问题和答案不会被自动恢复。晋级场景必须由复核者显式提交，并作为隔离测试数据校验。

## 复核字段

`POST /api/feedback/{feedback_id}/review` 只接受以下 JSON 字段：

```json
{
  "reviewer_id": "<reviewer-id>",
  "status": "confirmed",
  "attribution": "tool",
  "priority": "high"
}
```

`status` 可用 `pending`、`confirmed`、`rejected`；`attribution` 可用
`model`、`prompt`、`knowledge_base`、`tool`、`infrastructure`、`user_input`、`unknown`；
`priority` 可用 `low`、`medium`、`high`、`critical`。复核者只以 HMAC 指纹保存，不保存自由文本或原始身份标识。

## 查询复核

- `GET /api/reviews?trace_id=<trace-id>`：按 Trace 查询；也可使用 `feedback_id`、`status`、`limit` 和 `offset`。
- `GET /api/reviews/{review_id}`：读取单条复核和结构化晋级关联。

查询遵循 M15 的 30 天保留策略；过期 Trace 及其反馈、复核和晋级产物不可查询。

## 晋级 YAML 场景

只有 `confirmed` 且反馈类别不是 `correct` 的复核可以晋级。调用：

`POST /api/reviews/{review_id}/promote`

请求体中的 `scenario` 必须是现有 YAML DSL 的单个场景对象，例如：

```json
{
  "scenario": {
    "id": "vpn-recovery-regression",
    "name": "VPN recovery regression",
    "tags": ["feedback", "m16"],
    "conversation": [{"user": "VPN is unavailable"}],
    "expect": {"response": {"contains": ["ticket"]}}
  }
}
```

平台先拒绝授权头、密钥、Token、Cookie 等敏感字段和值，再使用现有
`SCENARIO_SCHEMA`、`load_scenario_text` 和安全 YAML 转储进行校验。成功响应包含
`promotion_id`、`feedback_id`、`trace_id`、`scenario_id` 和 `scenario_yaml`；重复晋级返回同一产物。

`GET /api/promotions/{promotion_id}` 可读取已保存的 YAML 和关联 ID。生成的内容可直接传给
`load_scenario_text`，再用现有 `ScenarioRunner` 和 Reference Agent adapter 离线执行；执行结果中的
scenario ID 可用于报告关联。平台不会把 Trace 明文、密钥或遥测令牌写入 YAML。

## 运行与边界

M16 的离线契约测试使用临时 SQLite 文件和占位环境变量。线上读接口、反馈与复核写入仍以受控平台访问为前提；正式网关鉴权和真实供应商调用不属于本里程碑。

趋势、线上离线对比和发布验证已在 M17 完成，详见趋势、线上离线关联与发布验证指南。真实公网环境、正式凭据和 PostgreSQL 遥测驱动仍不在当前交付范围内；M15 的 `telemetry-prune` 与 30 天保留策略继续有效。
