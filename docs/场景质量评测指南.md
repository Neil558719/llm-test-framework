# YAML 场景质量评测

声明 `quality` 后，每个检查都是 required。默认执行器和 CLI 不创建 Judge；没有显式 evaluator 时输出 `not_executed`，场景与运行门禁均阻断。原有14条确定性 API 场景没有 quality 声明，继续完全离线执行。

```yaml
quality:
  accuracy: {min_score: 0.8}
  relevance: {min_score: 0.8}
  faithfulness: {min_score: 0.8}
  helpfulness: {min_score: 0.8}
  hallucination: {max_rate: 0.2}
```

仅接受这五个名称及各自唯一的阈值字段；阈值是有限数值0..1（含边界），不接受布尔、字符串、未知字段或 optional/not_applicable 策略。`hallucination_rate` 不是这个 DSL 的字段名，须使用 `hallucination.max_rate`。旧任意 quality 元数据（例如 release_date）现在加载失败，元数据不应伪装成质量声明。

`accuracy` 保留为 Judge 对事实准确性的 rubric 名称，JSON 的 `score_kind=judge_rubric` 和 HTML 均明确其含义。它不是 gold accuracy，不创建正确/错误金标，不调用 `add_gold_result`；现有 A02 `mean_judge_score` 聚合保持。只有明确金标才能进入金标准确率分母。

显式离线接线示例：

```python
from functools import partial
from llmtest import Config
from llmtest.clients.mock_client import MockLLMClient
from qe_platform.adapters import ReferenceAgentAdapter
from qe_platform.workflow_runner import ScenarioRunner, evaluate_scenario_quality

judge = MockLLMClient(Config(mode="mock", mock_latency_ms=0))
evaluator = partial(evaluate_scenario_quality, client=judge)
runner = ScenarioRunner(ReferenceAgentAdapter.from_setup, quality_evaluator=evaluator)
# result = runner.run(scenario)
```

Mock 的 `provider=mock` 显示在 JSON/HTML 中，只证明离线接线。它可以按现有离线门禁规则完成 required 检查，不能用来声称真实模型质量或供应商效果。本轮没有新增 live 发布资格体系。没有 client 时，helper 同样返回 `not_executed`；即使进程环境为 real，也不会自行查询 registry 或创建 Mock/real Judge。

`run_gate(..., quality_evaluator=evaluator)` 接受同一个程序化入口。CLI 没有默认 Judge 开关；需要 quality 的资产必须由显式注入的调用方执行。底层 `llmtest` JudgeSpec 仍使用1..100原量纲，DSL的0.8映射为80，结果归一化为0..1；不会改底层 assert_llm_judge 的量纲，也不会钳位非法输出。

一次场景仅评完整执行后的最终响应，question 是产生该响应的最后实际用户问题，context 来自该响应的实际 sources。不会拼接所有问题冒充轨迹，也不会用前轮 sources 或回答代替最终证据。创建adapter失败或中途执行错误时，质量保留 `not_executed/execution_incomplete`，不调用 evaluator。确定性断言失败但对话执行完成时仍可评质量，质量通过不会抹去确定性失败。

faithfulness/hallucination 缺少非空 sources 时输出 `inconclusive/missing_grounding_context`，不调用该检查的 Judge。若声明同时包含其他可评指标，平台只将这些指标的声明副本交给回调，最后按原声明顺序合并全部 required 结果；全部缺 grounding 时不调用回调。空 claims 保留 A02 的 `None` 率值与 inconclusive，不按零幻觉通过，不加不适用豁免。

结果保留旧 `QualityCheckResult(metric, expectation, status, score, message)` 位置字段，新增 required、threshold、reason、provider、model、version。version 是 llmtest 接线版本，不冒充供应商未报告的模型修订；自定义回调没提供来源时 provider 显示 callback，其他字段保留空值，不推测真实来源。回调不能改变声明集、required 或阈值；缺失、重复、多余指标，非法状态/非有限分数、分数与状态冲突均记录 error。回调收到声明/响应副本，不能修改已保存的实际执行响应。异常仅保存受控 reason，不将原异常中的凭据文本放入质量报告。

显式自定义client也须返回有效测量：claims必须为list且内容为非空字符串，合法空list保留inconclusive；verify须返回claim匹配的ClaimVerdict，枚举限SUPPORTED/NOT_SUPPORTED/CONTRADICTED，confidence为有限0..1数值非bool，evidence为字符串。非法证据输出error/None，不算零幻觉。来源在本次测量返回后读取；未完成本次测量时不拿前次model冒充当前来源，冷默认model也不按client名称推测。

| required 质量状态 | complete | passed |
| --- | --- | --- |
| 所有 passed | 对话完整时true | 确定性断言也通过时true |
| 合法 failed | 对话完整时true | false |
| inconclusive / error / not_executed | false | false |

JSON 保留步骤响应、Trace、工具参数和 expected/actual 断言；HTML 展开失败差异、质量状态/原因/来源/阈值及 Trace，动态内容转义。存储表和 AppResponse 未改。回退可撤销本次隔离提交；会恢复旧静默忽略质量的缺陷，应保留本次负例与执行证据，不能把回退当作已满足质量门禁。
