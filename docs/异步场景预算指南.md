# 异步场景预算与资源边界

`AsyncScenarioRunner.run(scenario, *, budget=ExecutionBudget(...))` 是原生异步入口，返回既有 `ScenarioRunResult`。同步 `ScenarioRunner.run`、`DifyChatAdapter.send` 和 `v1_gate.run_gate` 保留原语义，不承诺可抢占的硬超时，也不使用 `to_thread` 冒充取消。新增 `AsyncApplicationAdapter`、`AsyncDifyAdapter`、`AsyncReferenceAgentAdapter` 与公开导出。

## 一个用例，一个截止时间

截止时间在排队前按事件循环单调时钟选定，覆盖 semaphore 排队、async limiter、初始化、请求、重试退避和 required 评测，不为每个阶段重新计时。默认 `max_attempts=1`、并发上限4；超时、次数、退避和清理窗口拒绝bool、非有限数、错误类型及非法范围。runner可在事件循环外构造，semaphore在首次run的实际循环创建；同一runner不得跨循环复用。

工厂可立即返回adapter或返回awaitable。立即工厂必须是不阻塞的构造器；同步阻塞函数不能被Python抢占。返回后仍会核对同一截止时间，过期后不再发送请求。async回调必须协作式await；回调捕获取消后晚返回，也不能把deadline改成成功或继续dispatch。取消事件优先于同tick完成，外部 `Task.cancel()` 在有限清理后继续传播 `CancelledError`；`budget.cancel_event` 则返回明确的cancelled结果。

`execution.stage_ms` 分别报告queue、init、rate_wait、request、backoff、evaluation、cleanup。它们不是SUT延迟，不应直接相加：清理等待取消展开时可能与请求/初始化收尾重叠。场景 `latency_ms` 仍是实际对话窗口，不包括初始化、初始排队和Judge；重试与已进入对话后的等待属于该窗口。未进入对话时保持null，不补零；A07响应/trace测量和首内容/模拟来源规则不变。

## 取消、重试与清理

chat和工具写入默认没有重试资格。只有adapter明确 `retry_safe is True`，且抛出 `AsyncApplicationAdapterError(retryable=True, effect_unknown=False)`，并有剩余attempt预算时才重试；schema、参数、断言失败不重试。Dify和Reference原生适配器均默认 `retry_safe=False`。尝试列表保存稳定的本地 `operation_key` 和实际结果；该key是审计标识，不是发给服务器的Idempotency-Key，不能据此宣称外部写入幂等。

请求提交后超时或取消可能已经产生外部副作用，使用 `effect_unknown` 保守记录，禁止在未知结果后自动重试；取消任务不等于撤销工单。连接建立前的已知失败与未知请求结果分开。错误证据只使用受控类型/原因，原异常文本和凭据不进入执行元数据。

runner默认拥有工厂返回的adapter并调用 `aclose`；`owns_adapter=False` 的借用adapter不关闭。Dify借用注入的HTTPX客户端时也不会关闭该客户端；调用者负责其生命周期。Reference本地工厂拥有HTTPX客户端和自建内存store。`cleanup_status=closed` 表示adapter的aclose成功，不表示关闭其内部借用的客户端。

`cleanup_timeout_s` 是用例截止后的独立有限清理宽限，不会重开请求或Judge预算。清理要排空worker/监控任务，关闭协程保留一部分时间用于取消finalizer；重复外部取消不会使清理任务失去监管。关闭协程自行取消按cleanup error记录，不假装调用者取消了用例；超时或清理失败都不能通过门禁。未取得permit不释放，无法协作取消的第三方回调报告 `unresponsive` 并保留对应permit，不宣称任务或资源已关闭。Python不能强制终止忽略取消或阻塞事件循环的任意插件。

## required评测与可信报告

`quality_evaluator` 必须是显式async函数/async可调用对象，返回既有 `QualityCheckResult` 列表。普通同步评测函数不会在事件循环内执行，required项保留 `not_executed/async_evaluator_required`，结果不可发布。async入口复用A05的grounding、required维度、阈值、score/status及来源校验；没有默认真实Judge。调用者仍需保证async实现没有内部阻塞同步SDK调用。

评测超时时保留已真实完成的对话步骤，不伪造未执行请求；required项保持未完成。`ScenarioRunResult.execution` 是追加可选字段，旧同步JSON省略它。A06原始报告校验、安全投影、持久reader均校验执行状态，deadline/cancelled/cleanup失败不能被重算成完整或获release资格。元数据有严格字段白名单，不接纳任意原始内容。

v1异步路径在执行前把 `budget.policy(max_concurrency)` 冻结进manifest的 `scoring_assets.execution_policy`；期限、attempt、退避、清理及并发策略变更会改变资产指纹，必须选择新baseline。自报manifest仍不能自授信。手动组合runner/report时，也应先选定同一policy并冻结manifest；含async执行字段的v2报告必须与受控policy匹配。

```python
import asyncio
from pathlib import Path
from qe_platform import scenarios
from qe_platform.v1_gate import run_gate_async
from qe_platform.workflow_runner import ExecutionBudget

asyncio.run(run_gate_async(
    asset_dir=Path(scenarios.__file__).parent / "assets" / "reference_agent",
    json_path="reports/async.json", html_path="reports/async.html",
    budget=ExecutionBudget(case_timeout_s=30), max_concurrency=4,
))
```

CLI通过 `python -m qe_platform.v1_gate --async --case-timeout 30 --max-concurrency 4` 显式启用；`--adapter dify` 使用明确的Dify配置/环境，程序入口也支持注入factory和config。同步CLI不能默默接受异步预算参数。安装环境应明确选择已安装包内的场景资产路径，不能假定当前目录是仓库。

## Python和回退

测试依赖在ci/dev明确声明pytest-asyncio。必要3.9导入修复仅限同一路径：slots在>=3.10保持，在3.9保留frozen/字段API；延迟授权模块注解求值；LangGraph状态的一个Optional；Python<3.10条件依赖eval-type-backport供Pydantic解析已有类型注解。没有升级原锁定包。已实际验证3.9.25和3.13.15的指定范围，不冒称验证所有支持版本。

没有数据库Schema迁移或历史结论回填，旧同步报告形状保留。新reader支持旧证明；旧reader可能拒绝带async状态的未完成证明，代码回退时应使用匹配的数据库快照，不删除或改写历史失败来获得通过。离线ASGI/Mock只能验证接线：服务端可能继续完成已提交工作，不证明真实provider/IdP/HTTPS或部署已经验收。E01真实流式、E02缓冲队列均不在本任务。
